## NavLink 켜짐 판정 (lib/dom/lib.js:388)
  isActive = locationPathname === toPathname
          || (!end && locationPathname.startsWith(toPathname)
                   && locationPathname.charAt(endSlashPosition) === '/')
  endSlashPosition = toPathname !== '/' && toPathname.endsWith('/')
                   ? toPathname.length - 1 : toPathname.length

end 실측표 (scratch/c1-navlink-end-probe.tsx)
  주소            to="/"   to="/"+end   to="/signup"   to="/signup"+end
  /               ON       ON           off            off
  /signup         off      off          ON             ON
  /signup/done    off      off          ON             off

→ end 는 to="/" 에서 결과를 한 칸도 안 바꾼다.
   to="/" 는 endSlashPosition=1 이고 '/signup'.charAt(1)==='s' 라
   두 번째 갈래가 애초에 안 걸린다.
   "루트 링크에 end 를 붙여라" 는 통설은 8.3.0 에서 근거 없음.
   end 가 갈리는 곳은 자식을 거느린 주소의 자식 페이지뿐.

## 라우트 표 규칙 (createMemoryRouter 로 재현)
- 자식 절대 경로: 부모들의 합친 주소로 시작해야 함. 아니면
    Absolute route path "/other" nested under path "/app" is not valid.
    An absolute child route path must start with the combined path of all its parent routes.
  부모가 '/' 면 모든 절대 경로가 통과 → 우리 앱에선 'signup' 과 '/signup' 이 동일.
  (초고에 "중첩이 깨진다" 로 적었다가 실측 후 정정)
- index: true 와 path: '' 는 렌더 결과 동일.
  차이는 index 가 자식을 못 가진다는 것 →
    Cannot specify children on an index route
