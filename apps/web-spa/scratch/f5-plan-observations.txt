6. strict mode 위반이 우리 앱에서 실제로 난다
════════════════════════════════════════════════════════════════

page.getByText('jaehoon', { exact: true }) →

  Error: strict mode violation: resolved to 3 elements:
    1) <span data-slot="sign-in" class="text-sm text-faint">jaehoon</span>
    2) <span class="text-sm font-semibold @lg:text-base">jaehoon</span>   (게시물 작성자)
    3) <strong>jaehoon</strong>                                          (댓글 작성자)

⇒ 로그인한 사람 · 게시물 작성자 · 댓글 작성자가 같은 글자다.
   F-3 의 「역할과 이름으로 찾는다」를 그대로 가져오면 걸리는 자리이고,
   답은 범위를 좁히는 것 — locator('[data-slot="sign-in"]').toHaveText('jaehoon')

⚠️ 이건 연출이 아니라 실제로 밟은 오류다. 지어낸 반례가 아니다.

→ ⚠️ 이 절의 답은 집필 단계에서 바뀌었다. data-slot 은 앱의 내부 표시라
   Playwright 가 오류 메시지에서 직접 제안한 locator('header') 로 갔고,
   idiomatic 한 getByRole('banner') 는 우리 마크업에서 0개다. 12절 참조.

12. 집필 단계 실측 (코드 박은 뒤)
════════════════════════════════════════════════════════════════

── codegen 실물 (헤디드 크로미움 · 상호작용 없이 종료) ────────────

  import { test, expect } from '@playwright/test';

  test('test', async ({ page }) => {
    await page.goto('http://localhost:5173/');
  });

  ⚠️ expect 를 가져오는데 안 쓴다. 학생이 그대로 두면 eslint 가 문다.
  ⚠️ 녹화는 「누른 것」만 적는다. 「그래서 무엇이 됐나」는 한 줄도 안 적는다.
     이것이 7절 함정의 뿌리 — 녹화만 한 판은 클릭하고 아무것도 안 본다.

── Step 3 충돌 (실물 파일로 재현) ────────────────────────────

  ❯ e2e/feed.spec.ts (0 test)
   FAIL  e2e/feed.spec.ts
  Error: Playwright Test did not expect test() to be called here.
  - You have two different versions of @playwright/test. …
  Test Files  1 failed | 152 passed (153)   ← 판 수는 안 준다(1061 그대로)

  고침 = vitest exclude 에 e2e/** + tsconfig include 에 e2e·playwright.config.ts
  ⚠️ tsconfig 를 안 고치면 E2E 코드가 타입 검사를 통째로 안 받는다(C-3 계열).
     탐침으로 확인 — e2e 에 `const _p: number = '글자'` → TS2322 로 잡힌다.

── Step 4 strict mode (타이밍 의존이라 더 고약하다) ──────────────

  A. 피드를 안 기다리고 로그인 → ✓ 통과
  B. 피드가 다 뜬 뒤 로그인   → ✘ strict mode violation: resolved to 3 elements

  ★ 순진한 판은 「틀려서」가 아니라 「통과해서」 위험하다.
    A 가 통과한 이유는 맞아서가 아니라 아직 안 그려져서다.

  getByText('jaehoon') = 3 · {exact:true} 도 3 (exact 여부와 무관)
  셋의 정체 = 머리말 sign-in · 게시물 작성자 · 댓글 작성자

  🚨 idiomatic 한 답이 우리 앱에서 안 통한다 — getByRole('banner') = 0
     Layout.tsx 의 <header> 가 <main> 안에 있다. HTML-AAM 상
     header 가 main·article·aside·nav·section 의 자손이면 banner 역할을 잃는다.
     그리고 getByRole 이 0개일 때는 오류가 아니라 그냥 안 맞는다(조용하다).
     ⇒ Playwright 가 오류 메시지에서 직접 제안한 locator('header') 로 갔다.
     ⚠️ 이건 실제 접근성 이슈이기도 하다(banner 랜드마크 없음). 다만 고치면
        Layout 재구조화라 스냅숏 판 여러 개가 물어 F-5 범위 밖 — 안 고쳤다.

  두 번째 사례(댓글) — 범위로는 못 풀고 exact 로 푼다
    card 안 getByRole('button', {name:'게시'})              = 2  ('게시물 …' 이 함께)
    card 안 getByRole('button', {name:'게시', exact:true})  = 1
