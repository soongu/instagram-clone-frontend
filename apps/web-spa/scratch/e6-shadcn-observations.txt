2. cn 실측 — "뒤엣것이 이긴다" 가 아니라 "덮을 수 있으면 앞엣것을 지운다"
--------------------------------------------------------------------------------

  그냥 이어붙이기            ['px-2.5','px-6'].join(' ')  → "px-2.5 px-6"  (둘 다 남음)
  cn                        cn('px-2.5','px-6')          → "px-6"
  clsx 만                   clsx('px-2.5','px-6')        → "px-2.5 px-6"  (안 지움)
  twMerge 만                twMerge('px-2.5','px-6')     → "px-6"

  안 겹치는 것은 산다        cn('px-2.5 py-1 text-sm','px-6') → "py-1 text-sm px-6"

  ⚠️⚠️ 방향이 있다:
     cn('px-6','p-4')  → "p-4"          p-4 가 px-6 을 통째로 덮으므로 앞엣것 삭제
     cn('p-4','px-6')  → "p-4 px-6"     px-6 은 p-4 의 일부만 덮으므로 둘 다 남음

  갈래가 다르면 못 민다:
     cn('ring-1 ring-foreground/10','border border-line')
       → "ring-1 ring-foreground/10 border border-line"   ← 테두리가 두 겹이 된다
     cn('ring-1 ring-foreground/10','ring-0') → "ring-foreground/10 ring-0"

  우리 토큰 ↔ shadcn 토큰(같은 갈래면 우리가 이긴다):
     cn('bg-card','bg-surface')            → "bg-surface"
     cn('text-card-foreground','text-ink') → "text-ink"
     cn('rounded-xl','rounded-lg')         → "rounded-lg"

  진짜 자리 — Button 에 px-6 을 넘기면:
     buttonVariants({className:'px-6'})      38개 · px-2.5 와 px-6 이 **둘 다** 있음
     cn(buttonVariants({className:'px-6'}))  37개 · px-2.5 만 사라짐

  clsx 쪽:  cn('base', false && 'never', {on:true, off:false}, ['arr']) → "base on arr"


3. ⚠️⚠️ 들여온 Card 는 <div> 다 — 화면은 거의 같은데 문서 구조가 바뀐다
--------------------------------------------------------------------------------

  우리가 B-3 에서 짠 Card 는 <article> 이었다. 들여온 Card 는 <div> 다.
  색·모서리는 눈으로 구별하기 어려운데 낭독기에게 "여기부터 하나의 글" 이라고
  알려주던 표시가 사라진다.

  파일이 우리 것이므로 열어서 고쳤다:
    - }: React.ComponentProps<"div">  →  }: React.ComponentProps<"article">
    - <div data-slot="card"           →  <article data-slot="card"

  ⚠️ 이 수정은 `add card` 를 다시 하면 날아간다. 단 CLI 가 먼저 알려준다:
       npx shadcn@latest add card --dry-run  → "⚠ 1 file will be overwritten."
       npx shadcn@latest add card --diff     → 우리가 지운 줄까지 그대로 보여준다
     조용히 사라지는 것이 아니라 **물어본다.** 복사 방식의 비용은 여기서 낸다.

  같은 이유로 고친 두 번째 자리 — dialog.tsx 의 닫기 버튼:
    <span className="sr-only">Close</span>  →  <span className="sr-only">닫기</span>
    (DialogFooter 의 "Close" 도 "닫기" 로)
    한국어 화면인데 낭독기만 영어로 읽고 있었다.


4. ⚠️ 들여온 Avatar 는 사진이 오기 전에 <img> 를 아예 안 그린다
--------------------------------------------------------------------------------

  renderToStaticMarkup(<Avatar><AvatarImage src=…/><AvatarFallback>J</AvatarFallback></Avatar>)
    → <span data-slot="avatar" …><span data-slot="avatar-fallback" …>J</span></span>
      img 태그 **0개**

  jsdom 도 같다(이미지를 실제로 안 받아오므로 영영 loaded 가 안 된다).
  브라우저에서는 정상적으로 <img data-slot="avatar-image"> 로 바뀐다.

  Base UI 의 판단 지점(avatar/image/useImageLoadingStatus.js):
      const image = new window.Image();
      image.onload = …;  image.src = src;
      if (image.complete) setLoadingStatus(image.naturalWidth > 0 ? 'loaded' : 'error');
                          ^^^^^^^^^^^^^^ 이 fast-path 가 동기다

  => test-setup.ts 에 "이미 받아둔 이미지" 로 답하게 깔면 jsdom 에서도 <img> 가 나온다.
     (E-5 의 matchMedia stub 과 같은 성격 — jsdom 에 없는 것을 메우는 것)
       HTMLImageElement.prototype.complete     → true
       HTMLImageElement.prototype.naturalWidth → 1
     이 한 줄로 20건 넘게 살아났고, 서버에서 그리는(SSR) 비교만 따로 손봤다.

  ⚠️ SSR 은 layout effect 를 안 돌리므로 stub 과 무관하게 대체 글자만 나온다.
     이것은 버그가 아니라 실제 동작이다(서버는 사진이 뜨는지 알 수 없다).


5. ⚠️⚠️⚠️ 백그라운드 탭에서 잰 포커스 측정은 전부 거짓이었다 (가장 중요)
--------------------------------------------------------------------------------

  처음 브라우저에서 잰 결과:
    · 모달을 열어도 포커스가 트리거에 그대로 있다
    · Tab 을 누르면 팝업 **밖으로 나간다** (aria-hidden 걸린 영역의 input 으로)
    · Esc 로 닫아도 팝업이 DOM 에 남아 있다

  => "Base UI 는 포커스를 안 가둔다" 로 결론 낼 뻔했다. **틀렸다.**

  소스를 읽고 원인이 나왔다
  (floating-ui-react/components/FloatingFocusManager.js + utils/enqueueFocus.js):

      onFocus: () => { if (modal) void enqueueFocus(getTabbableContent()[0]); }
      function enqueueFocus(el, …) { … requestAnimationFrame(exec) … }
                                         ^^^^^^^^^^^^^^^^^^^^^^^

  포커스를 되돌리는 일이 **rAF 안에서** 일어난다. 그런데 백그라운드 탭에서는
  rAF 가 아예 안 돈다. 그래서 가두는 손이 멈춰 있었던 것이다.
  (팝업이 안 사라진 것도 같은 이유 — 나가는 애니메이션이 안 끝난다.)

  확인: document.visibilityState → "hidden" (탭이 앞에 없음)

  rAF 를 타이머로 대신 채우고 다시 재니 전부 정상:
      window.requestAnimationFrame = (cb) => setTimeout(() => cb(performance.now()), 16);

    · 열면 포커스가 팝업 안으로 들어간다                    ✅
    · Tab 을 6번 눌러도 팝업 안(닫기 버튼)에 머문다          ✅

  ⚠️ 교훈: 브라우저에서 잰 값이라고 참이 아니다. **탭이 앞에 있는지**부터 본다.
     시간·프레임에 기대는 동작(포커스 이동·애니메이션·전환)은 특히 그렇다.
  ⚠️ 백그라운드 탭은 setTimeout 도 조인다. 250ms × 12 회 루프를 돌렸다가
     렌더러가 45초 동안 응답을 안 해 CDP 가 끊겼다. 긴 폴링을 걸지 말 것.

  목록                          결과   무엇으로 확인했나

     자기 개발자 도구에서 aria-modal 을 찾다가 못 찾는다.

       제목 없을 때 aria-labelledby → 없음 / aria-describedby → 없음

  트리거 쪽도 딸려온다: aria-haspopup="dialog" · aria-expanded 가 열림 상태를 따라간다


7. 두 토큰 체계 — 밝은 화면에선 똑같고 어두운 화면에서만 갈린다
--------------------------------------------------------------------------------

  들여온 Card 를 그대로 쓰면 카드 배경이 shadcn 의 --card 를 쓴다.
  우리 회원가입 판은 우리 --color-surface 를 쓴다.

    밝은 화면   회원가입 판 oklch(1 0 0)      카드 oklch(1 0 0)       **같다**
    어두운 화면 회원가입 판 oklch(0.182 …)    카드 oklch(0.205 …)     **다르다**

  => 밝은 데서 보면 아무 문제가 없다. 어두운 데서만 두 판의 회색이 갈린다.
     E-5 의 "테스트는 초록인데 화면이 깨져 있었다" 와 같은 종류의 함정.

  화해 — className 으로 매번 덮지 않고 **값을 잇는다**(globals.css):

    :root {
      --card:               var(--color-surface);
      --card-foreground:    var(--color-ink);
      --popover:            var(--color-surface);
      --popover-foreground: var(--color-ink);
      --border:             var(--color-line);
    }

  그리고 shadcn 의 .dark 블록에서 그 다섯 줄을 **지웠다.**
  우리 토큰이 .dark 에서 이미 갈리므로 참조가 저절로 따라온다.
  (E-2 의 "값과 조건을 갈라 둔다" 가 여기서 한 번 더 쓰인다.)

  화해 후 재측정 (어두운 화면):
    회원가입 판 oklch(0.182 0 none) · 카드 oklch(0.182 0 none) → **같다**
    카드 글자색 oklch(0.97 …) = 우리 --color-ink
    푸터 윗선  oklch(0.333 …) = 우리 --color-line

  ⚠️ className 으로 덮는 길도 된다(cn 이 밀어내므로). 다만 카드마다·상자마다
     매번 적어야 하고, ring 처럼 갈래가 다른 것은 안 밀리므로 ring-0 을 따로 붙여야 한다.
     값을 잇는 쪽이 한 곳에서 끝난다.

10. 모달을 여는 자리 — 사진이 아니라 "댓글 모두 보기"
--------------------------------------------------------------------------------

  E-5 Step 1 은 "사진을 누르면 크게 뜨는 그거" 로 모달을 소개했다.
  그런데 사진에는 A-4 부터 **두 번 누르면 좋아요** 가 붙어 있다.
  한 번 누르기로 모달을 열면 두 번 누를 때 모달이 먼저 열린다(두 번 누르기는
  한 번 누르기를 두 번 발생시킨다 — 명세).

  그래서 여는 자리를 "댓글 N개 모두 보기" 로 옮겼다. 실제 인스타그램도
  피드에서 사진을 누르면 아무 일도 안 하고, 댓글 줄을 눌러야 게시물이 열린다.
