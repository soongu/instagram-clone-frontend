근거: TanStack/query issue #9660 · PR #9615

설치본 .d.ts 가 적고 있는 것:
  mutationFn: (variables, context) => Promise<TData>
  onMutate:   (variables, context) => TOnMutateResult
  onSuccess:  (data, variables, onMutateResult, context)
  onError:    (error, variables, onMutateResult, context)
  onSettled:  (data, error, variables, onMutateResult, context)

  MutationFunctionContext = { client: QueryClient; meta; mutationKey? }
  제네릭 이름도 TContext -> TOnMutateResult 로 개명

시중 자료(그리고 5.89.0 이전 문서)는 전부 3인자다:
  onError: (err, variables, context) => ...   // 여기서 context = onMutate 반환값

런타임 실측 (scratch/c6-mutation-signature-probe.test.tsx · 5/5 통과)
  - mutationFn 이 받는 인자 개수 = 2. 두 번째의 키는 정확히
    ['client', 'meta', 'mutationKey'] 이고 client 는 그 판의 QueryClient 와 동일 객체
  - onMutate 의 두 번째 인자로 온 context.client.setQueryData 가 실제로 캐시를 바꾼다
    (useQueryClient() 를 안 불러도 된다)
  - onError 가 받는 인자 개수 = 4 · onSettled = 5
    onError[2] = onMutate 가 돌려준 값 · onError[3].client = 그 판의 QueryClient
  - *** 옛 3인자 형태는 그대로 동작한다 *** — 위치가 같아서 값도 같다.
    onMutate 스냅샷 -> onError 롤백이 정상 복원됨('처음' 으로 되돌아옴)
