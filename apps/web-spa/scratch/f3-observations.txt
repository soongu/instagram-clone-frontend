================================================================

   F-3 에서 실제로 값을 한다.

7절. fireEvent 는 75개 파일 중 단 1개 파일에 3건
================================================================

  user-event 쓰는 파일   75
  fireEvent 쓰는 파일     2  (c7-escape-hatch.test.tsx 3건 + c7-observations.txt 언급)

그 1건의 이유는 C-7 채증에 적혀 있다 — 렌더 횟수를 셀 때 act() 밖의 raw .click()
이 상태 갱신을 안 일으켜서 fireEvent.click 으로 바꿨다.

=> "userEvent 우선, fireEvent 는 예외" 가 저장소 숫자로 이미 증명돼 있다.

⚠️ 초안 측정이 틀렸다 — 두 방법을 같은 화면에서 이어 쟀더니:
     userEvent.type(input,'abc')            onChange 3회
     fireEvent.change(input,{value:'abc'})  onChange 0회   ← 거짓
   값이 이미 'abc' 라 같은 값을 다시 넣은 것이라 아무 일도 안 일어난 것이었다.
   화면을 새로 그려(cleanup 후 render) 재측정한 참값:
     userEvent.type   3회 — "a" / "ab" / "abc"   (한 글자씩)
     fireEvent.change 1회 — "abc"                (통째로)

★ await 를 빼면 클릭이 아예 안 일어난다:
     const p = userEvent.click(button);
     await 전 호출 0회  →  await 후 호출 1회

10절. 부수 실측
================================================================

- <form> 은 이름이 없으면 역할이 없다 — queryByRole('form') = null.
  폼 자체를 찾지 말고 안에 있는 것들(입력칸·버튼)로 찾는다.

- likeCount 0 이면 개수 문단이 아예 안 그려진다 ({likeCount > 0 && …}).
  queryBy 가 필요한 진짜 자리.

- 하트가 둘이면 getByRole 이 던진다:
    Found multiple elements with the role "button" and name "좋아요"
  getAllByRole 로 2개, { pressed: true } / { pressed: false } 로 1/1 로 갈린다.

- 매처 실패 메시지 대조:
    toBeDisabled()          "expect(element).toBeDisabled() … Received element is not disabled: <button …>"
    .disabled toBe(true)    "expected false to be true"
  같은 사실을 확인하는데 알려주는 양이 다르다.

- 댓글 폼: 처음 잠김 → 글자 넣으면 풀림 → 게시하면 onSubmit('노을 예쁘네요') +
  입력칸 '' 로 비워짐 → 공백만 넣으면 잠긴 채(useCommentInput 이 trim 한다)
  → 엔터로도 제출된다(진짜 <form> 이라 submit 이 걸린다).

- 가드는 전부 일부러 깨서 확인했다:
    aria-label 제거      → 판 2건 실패 + tsc TS2741
    aria-pressed 제거    → 판 1건 실패
    likeCount>0 조건 제거 → 판 1건 실패
    onClick 제거         → 판 1건 실패
    disabled={isEmpty} 제거 → 판 2건 실패
    trim 제거            → 판 1건 실패
