4. 🚨🚨🚨 채증(H-3b) 7절의 파일별 내역이 틀렸다 — 총계는 맞고 이름이 틀렸다
---------------------------------------------------------------------
커버리지 도구를 다시 만들어 돌렸더니 같은 10,147 B 가 다른 파일로 나왔다.

  H-3b 채증   10,147 B ← routes/PostDetailPage.tsx
  내 첫 도구  10,147 B ← src/api/comments.ts

같은 바이트 · 다른 이름 → 둘 중 하나는 틀렸다는 뜻인데, 소스 크기를 재니 둘 다 틀렸다:

  src/api/comments.ts             484 B  →  10,147 B ?  (21배)
  src/routes/PostDetailPage.tsx  2,264 B  →  10,147 B ?  (4.5배)

  압축된 번들 조각이 원본 소스보다 클 수 없다.

원인: 안 쓴 구간 하나에 이름을 하나만 붙였다.
  한 구간이 여러 모듈에 걸쳐 있는데 시작점만 소스맵에 찍어 이름을 달면,
  그 구간 전체가 경계에 서 있던 파일 하나의 몫으로 쌓인다.
  → 구간 안에서 소스맵 항목이 바뀌는 자리마다 잘라 나누도록 고쳤다
    (이진 탐색으로 같은 항목이 이어지는 끝을 찾는다).

검증 셋 — 전부 통과:
  (a) 총계 재현      418,120 B / 61.3% — H-3b 채증과 바이트까지 동일
  (b) 파일별 타당성   여섯 파일 전부 원본 소스보다 작아졌다(압축의 정상 결과)
  (c) 트리맵 독립 대조 아래 표

      꾸러미            트리맵(압축 전)   커버리지+소스맵(압축 후)

      @sentry/core           12.2%              12.6%

  완전히 다른 도구가 다른 단계에서 잰 것인데 꾸러미마다 1~3%p 안에서 맞는다.
