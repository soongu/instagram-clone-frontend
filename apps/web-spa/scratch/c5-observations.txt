----------------------------------------------------------------

      core/api/HelloController.java   ← 이것 하나뿐

  즉 게시물 API 가 없다. ApiResponse 만 있다:
      public record ApiResponse<T>(boolean success, T data, String message)
      ok(data)      → { success:true,  data,       message:null }
      error(message)→ { success:false, data:null,  message }

  레거시 instagram-clone-with-jpa202502 에는 PostController·CommentController·
  AuthController 가 전부 있지만 봉투가 다르다:
      record ApiResponse<T>(boolean success, T data, ErrorResponse error)
      → 실패가 { success:false, data:null, error:{ code, message } }
  과목 canon 은 v2 쪽(message 한 칸)이라 레거시를 그대로 쓰면 어긋난다.

  => 사용자 승인으로 apps/api-stub/server.mjs 를 세웠다. Node 내장 http 만
     쓰므로 설치할 것이 없고, v2 봉투를 그대로 말한다.

5. Step 2 실측 — fetch 와 Axios 가 404 에서 갈린다
----------------------------------------------------------------
  검증 파일: src/api/c5-fetch-vs-axios.test.ts (10건 통과)

  fetch  404 에 reject 하지 않는다 (catch 가 안 불린다)
         response.ok=false · response.status=404 두 값으로만 갈린다
         본문을 읽으려면 await 이 한 번 더
         연결 자체가 안 될 때만 던진다
  Axios  AxiosError 로 던진다. error.response.status=404 ·
         error.response.data.message 에 서버가 보낸 사유
         성공 응답은 body 를 이미 풀어서 준다 (await 한 번)
  validateStatus 기본값 실측: 200 true · 299 true · 300 false ·
         404 false · 500 false
