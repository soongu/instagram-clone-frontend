  즉 게시물 API 가 없다. ApiResponse 만 있다:
      public record ApiResponse<T>(boolean success, T data, String message)
      ok(data)      → { success:true,  data,       message:null }
      error(message)→ { success:false, data:null,  message }

  레거시 instagram-clone-with-jpa202502 에는 PostController·CommentController·
  AuthController 가 전부 있지만 봉투가 다르다:
      record ApiResponse<T>(boolean success, T data, ErrorResponse error)
      → 실패가 { success:false, data:null, error:{ code, message } }
  과목 canon 은 v2 쪽(message 한 칸)이라 레거시를 그대로 쓰면 어긋난다.

  => 사용자 승인으로 apps/api-stub/server.mjs 를 세웠다. Node 내장 http 만

2. 연습용 서버 실측 (DELAY_MS=0 으로 띄워 curl 로 확인)
----------------------------------------------------------------
  GET  /api/posts            → 200 { success:true, data:[10장], message:null }
  GET  /api/posts/999        → 404 { success:false, data:null,
                                     message:"게시물을 찾을 수 없습니다" }
  POST /api/posts/1/like     → 401 { ..., message:"로그인이 필요합니다" }  (토큰 없음)

  로그인 → 토큰 발급:
  POST /api/auth/login {"username":"jaehoon"}
       → { accessToken:"access-1", refreshToken:"refresh-2", user:{...} }

  좋아요 1~5회 (매번 새 토큰):
       1회 200 liked:true  likeCount:1241
       2회 200 liked:false likeCount:1240
       3회 200 liked:true  likeCount:1241
       4회 200 liked:false likeCount:1240
       5회 500 { success:false, message:"좋아요를 저장하지 못했습니다" }
       → LIKE_FAIL_EVERY=5 가 실제로 다섯 번째에서 떨어진다 (롤백 교보재)

  같은 액세스 토큰으로 4회 (ACCESS_TOKEN_USES=3):
       1회 200 · 2회 200 · 3회 200 · 4회 401
       → 401 갱신을 눈으로 볼 수 있다

3. Step 1 실측 — 직접 effect+fetch 로 짠 판
----------------------------------------------------------------
  검증 파일: src/routes/c5-effect-fetch.test.tsx (11건 통과)

  (a) 첫 페인트에 게시물이 0장

  (b) 봉투를 열어봐야 실패를 안다
      500 + { success:false, message:"피드를 만들지 못했습니다" } 를 내려도
      fetch 는 reject 하지 않는다. body.success 를 보고서야 오류 화면이 뜬다.
      (Step 2 에서 이 함정을 정면으로 다룬다 — Axios 는 여기서 갈린다)

  (c) ★ StrictMode 에서 화면 하나에 요청이 두 번
      requestLog === ['GET /api/posts', 'GET /api/posts']
      B-4 의 이중 실행이 "리스너 두 번" 이 아니라 "요청 두 번" 으로 돌아왔다.

  (d) 같은 피드를 두 곳에서 그리면 요청도 두 번
      HomePage 를 나란히 두 번 그리면 requestLog 길이 2 · 카드 20장.
      두 화면이 같은 데이터를 봐도 공유되는 것이 없다.

  (e) ★ 초기값 함정 — 나중에 도착한 배열은 안 들어간다
      render(<FeedSection posts={[]} />) → 카드 0장
      rerender(<FeedSection posts={allPosts} />) → 여전히 카드 0장
      useFeed 안이 useReducer(feedReducer, createFeedState(initialPosts)) 이고
      초기값은 첫 렌더에서 한 번만 읽힌다 (A-5 회수).
      => 그래서 HomePage 는 "데이터가 온 뒤에 FeedSection 을 마운트" 하는 쪽으로
         갔다. 부모가 useFeed(posts) 를 부르는 판은 영영 빈 화면이 된다.

  (f) 린트 — setState 를 effect 본문에서 부르지 않았으므로 통과
      C-2 가 남긴 scratch/c2-effect-lint.txt 의 react-hooks/set-state-in-effect
      는 effect 본문에서 곧바로 부를 때만 뜬다. .then 콜백 안은 안 뜬다.
