[4] Step 2 — create<T>()(...) 커리는 "필수" 가 아니다
-----------------------------------------------------
tsc 6.0.3 --strict 실측 (scratch/c4-curried-probe.ts):
  (A) create<Counter>()((set) => ...)                 → 통과
  (B) create<Counter>((set) => ...)   커리 없음        → ★ 통과 (에러 0)
  (C) create<Counter>()(persist(...))                 → 통과
  (D) create<Counter>(persist(...))   커리 없음+미들웨어 → ★ TS2345
      "Argument of type 'StateCreator<Counter, [], [[\"zustand/persist\", Counter]]>'
       is not assignable to parameter of type 'StateCreator<Counter, [], []>'"
  (E) create((set) => ...) 타입 인자 없음              → TS7006 (set 안쪽 state 가 any)
  => 정확한 규칙: **커리는 미들웨어를 얹을 때 필요하다.** 미들웨어가 없으면 둘 다 된다.
     "커리가 필수" 로 쓰면 사실 오류.

C-3 Step 1 과의 정면 대조 (같은 판에서 나란히 측정)
  커스텀 훅 두 곳 → 쓴 쪽만 바뀌고 읽는 쪽은 '없음' 그대로
  store 훅 두 곳  → 읽는 쪽이 즉시 같은 값을 본다
  ★ 감싼 것이 하나도 없다. Provider 도 문맥도 없이 그냥 render.

★ 위아래 관계가 사라진다: ConfirmDialog 를 <section> 안에, CommentList 를 <article> 안에
  두고 **상자를 먼저** 그려도 동작한다. Context 라면 Provider 가 위에 있어야 한다.

⚠️ 다만 "아무것도 안 늘어난다" 는 아니다 — AppProviders 에 <ConfirmDialog /> 한 줄이
   늘었다. 늘지 않은 것은 **감싸는 Provider** 다. 교안에서 이 구분을 흐리지 말 것.
