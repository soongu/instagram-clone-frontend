1. ⚠️⚠️ 컨테이너를 세우는 줄은 E-6 에서 이미 들어와 있었다 — 묻는 줄만 0건이었다
--------------------------------------------------------------------------------

  E-6 이 복사해 온 card.tsx:30 에 @container/card-header 가 있다.
  빌드 CSS 에서:

    .\@container\/card-header{container:card-header/inline-size}

  그런데 @container ( ... ) 조건절은 파일 전체에 **0건** 이었다.
    grep -o "@container[^{]*" dist/assets/*.css | sort | uniq -c
      1 @container\/card-header      ← 통을 세우는 줄(클래스)
                                     ← 묻는 줄은 없음

  => 통은 세워져 있는데 아무도 묻지 않는 상태. E-7 의 출발점이 여기다.

  우리 피드는 그때까지 창에게 물었다:
    @media (width>=62.25rem)         ← --breakpoint-2col: 62.25rem


2. ⚠️⚠️⚠️ E-4 회수가 두 겹이다 — 조건엔 var() 를 못 쓰는데 :root 엔 이름이 있다
--------------------------------------------------------------------------------

  E-4 의 결론: --breakpoint-* 는 빌드 CSS 의 :root 에 0건.
              미디어 쿼리 조건은 var() 를 못 읽기 때문.

  컨테이너 쪽도 똑같다. --container-2col: 60.25rem 을 선언하고 @2col: 를 쓰면:

    @container (width>=60.25rem)     ← 값이 박혀서 나온다
    grep -c "--container-2col" → 0   ← :root 에 없다

  그런데 여기서 갈린다 — --container-sm 과 --container-lg 는 :root 에 **있다**.

    :root  … --container-sm:24rem;--container-lg:32rem; …
    @media (width>=40rem){ .sm\:max-w-lg{max-width:var(--container-lg)} }
                                                       ^^^^^^^^^^^^^^^^

  => --container-* 는 한 이름으로 두 가지 일을 한다.
       조건으로 쓰일 때(@sm: · @2col:)  → 값이 박히고 :root 에 안 남는다
       값으로 쓰일 때(max-w-sm · max-w-lg) → var() 로 읽으므로 :root 에 남는다

     E-4 를 "토큰은 조건에 못 쓰니까 :root 에 안 나온다" 로 외운 학생은
     :root 에서 --container-sm 을 보고 정확히 틀린 결론을 낸다.
     남아 있는 이유가 조건이 아니라 **폭 값** 이기 때문이다.


3. ⚠️⚠️ 토큰 이름을 옮기면 다른 곳의 2col: 이 경고 없이 죽는다
--------------------------------------------------------------------------------

  --breakpoint-2col 을 --container-2col 로 바꾸는 순간, @ 가 없는 2col: 은
  전부 존재하지 않는 변형이 된다. 그런데:

    · 빌드는 성공한다
    · 경고가 하나도 안 나온다   (npm run build 2>&1 | grep -i warn → 없음)
    · 클래스 문자열은 JSX 에도 DOM 에도 그대로 남는다
    · 빌드 CSS 에서 규칙만 0건이 된다

      2col\:mb-0            → 0건
      2col\:max-w-\[470px\] → 0건

  실제로 죽었던 두 곳:
    PostCard    mb-6 2col:mb-0            두 열일 때 카드 아래 여백이 안 지워짐
    SignUpForm  p-4 2col:max-w-[470px]    통이 넓어지면 폼이 따라 늘어남

  둘 다 밝은 화면·좁은 창에서는 안 드러난다. E-5 의 "확인은 전부 초록인데
  화면이 깨졌다" · E-6 의 "밝은 화면에선 두 판이 똑같다" 와 같은 계열.

  ⚠️ 검증 중 내가 낸 실수 — grep 이스케이프를 잘못 써서
     @2col\:max-w-\[470px\] 를 "0건" 으로 읽고 살아나지 않았다고 판단할 뻔했다.
     실제로는 5개 규칙이 전부 있었다. 셸 인용부호를 거치는 패턴은
     결과가 0 일 때 한 번 더 다른 방법으로 확인할 것.

  가드: e7-visual-polish.test.tsx 의
        "창을 보던 2col: 이 화면 어디에도 안 남았다"
        → expect(html).not.toMatch(/(?<!@)2col:/)
        SignUpForm 을 일부러 되돌려 실제로 잡히는 것 확인함.

9. Step 4 — 문자를 아이콘으로 (lucide-react 1.31.0)
--------------------------------------------------------------------------------

  바꾼 곳 둘:
    PostHeader   ⋯  →  <Ellipsis className="size-5 @lg:size-6" />
    CommentList  ×  →  <X className="size-4" />

  className 문자열은 한 글자도 안 건드렸다. 이유는 아래 "안 지운 것" 참고.

  실제로 나오는 마크업(서버 렌더 결과):

    <svg xmlns="..." width="24" height="24" viewBox="0 0 24 24" fill="none"
         stroke="currentColor" stroke-width="2" stroke-linecap="round"
         stroke-linejoin="round" class="lucide lucide-ellipsis size-5 @lg:size-6"
         aria-hidden="true"><circle .../><circle .../><circle .../></svg>

  ⚠️ aria-hidden="true" 는 우리가 안 적었는데 붙는다.
     Icon.mjs:  ...!children && !hasA11yProp(rest) && { "aria-hidden": "true" }
     hasA11yProp = prop 이 aria- 로 시작하거나 role/title 이면 true.
     => 아이콘에 aria-label 을 붙이는 순간 이 숨김이 사라진다.
        일부러 aria-label="더보기" 를 붙여 가드가 잡히는 것 확인함(1건 FAIL).

10. Step 5 — 좋아요 줄을 인스타그램처럼
--------------------------------------------------------------------------------

  테두리 박스 버튼 + 글자('♡ 좋아요' / '♥ 좋아요 취소') 를 아이콘 버튼으로 바꿨다.

    <IconButton className="cursor-pointer p-2 ...ring" aria-label="좋아요" aria-pressed={liked}>
      <Heart className={`size-6 ${liked ? 'fill-current text-danger' : ''}`} />
    </IconButton>

  ⚠️ 여기서 갈림이 한 겹 옮겨갔다.
     E-2:  버튼 자신이 border-danger / text-danger 로 갈렸다
     E-7:  버튼 클래스는 눌리든 안 눌리든 같고, 갈리는 곳은 안쪽 아이콘이다


10-1. ⚠️⚠️ 이름이 안 바뀌게 되면서 aria-pressed 가 없으면 안 되는 몸이 됐다
--------------------------------------------------------------------------------

  글자가 있을 때는 이름 자체가 상태였다: '♡ 좋아요' → '♥ 좋아요 취소'.
  아이콘만 남으면 이름은 늘 '좋아요' 다. 그래서 눌림은 aria-pressed 가 든다.

  이건 E-5 의 밝기 버튼에서 이미 쓴 표시다(ThemeToggle 의 aria-pressed).
  다만 그쪽은 글자 버튼이라 "있으면 좋은 것" 이었고, 여기서는 없으면 상태를
  알 길이 아예 없어진다.

  일부러 aria-pressed 를 지워보니 **17개 테스트가 깨졌다**(9개 파일).
  Button.tsx 에 'aria-pressed'?: boolean 을 한 줄 더한 것이 이번 Step 의
  프로덕션 변경 중 유일하게 B-3 컴포넌트를 건드린 자리다(선택 prop 이라
  안 넘기면 속성 자체가 안 붙어서 b3-button 의 HTML 비교는 그대로 통과).


10-2. blast radius 가 이번 모듈에서 가장 컸다 — 9개 파일 19건
--------------------------------------------------------------------------------

  '♡ 좋아요' / '♥ 좋아요 취소' 로 버튼을 찾던 곳이 전부 물었다.

    이름으로 찾던 것 → { name: '좋아요', pressed: false | true }
      a4-typing(4) · b3-button(2) · b3-composition(2) · b3-use-like-toggle(3)
      · b3-use-toggle(1) · b4-toast(3)
    글자를 단언하던 것 → aria-pressed 단언으로
      b2-lifting(2) · b2-immutability(1)
    HTML 을 글자 단위로 견주던 것 → 그 자리만 표시로 맞추고 나머지 비교
      b3-snapshots(2) · b3-button(1)

  ⚠️ 함정 하나 — b3-button 에는 LikeButton 과 무관하게 **자기 JSX 로** '♥ 좋아요 취소'
     를 그리는 테스트가 따로 있다(Button 이 태그 섞인 children 을 받는지 보는 것).
     일괄 치환하면 이것까지 바꿔버린다. 실제로 한 번 바꿨다가 되돌렸다.

  브리지에 withSameLikeArea() 를 새로 뒀다. 아바타 자리를 [프로필자리] 로 맞추던
  것과 같은 방식으로 좋아요 버튼을 [좋아요자리] 로 맞춘다.
  toVisibleText 도 이걸 거치게 했다 — 안 그러면 아이콘은 태그가 벗겨지며 사라지고
  B-3 쪽 '♡ 좋아요' 글자만 남아 내용 비교가 어긋난다.

  ⚠️ BRIDGE 에서 like-button / like-button liked 두 줄은 지웠다.
     눌린 것과 안 눌린 것의 클래스가 같아져서 되돌릴 짝이 없어졌기 때문이다.


10-3. 왼쪽 끝을 맞추는 일 — 아이콘 버튼의 안쪽 여백만큼 바깥에서 뺀다 (브라우저 실측)
--------------------------------------------------------------------------------

11. Step 6 — 누르면 반응하게 (tw-animate-css 1.4.0 실측)
--------------------------------------------------------------------------------

  이 꾸러미는 **CSS 파일 하나뿐**이다(dist/tw-animate.css 14,880 B). JS 가 없다.
  globals.css 의 @import "tw-animate-css" 한 줄이 전부다.

  구조가 재밌다 — 애니메이션은 딱 둘(enter · exit)이고, 나머지 유틸리티는
  그 키프레임이 읽는 변수를 세팅만 한다.

    --animate-in: enter var(--tw-animation-duration,var(--tw-duration,.15s)) ...
    @keyframes enter { from {
      opacity: var(--tw-enter-opacity,1);
      transform: translate3d(...) scale3d(var(--tw-enter-scale,1),...) ...
    }}
    @utility zoom-in-*  { --tw-enter-scale: ... }
    @utility fade-in-*  { --tw-enter-opacity: ... }

  => fade-in-0 과 zoom-in-95 를 함께 쓰면 둘 다 먹는 이유가 이것이다.
     애니메이션이 둘 겹치는 게 아니라 한 키프레임의 변수 둘을 채우는 것이다.
     duration-200 이 먹는 것도 --tw-duration 을 읽기 때문이다(실측 0.2s).

  우리가 넣은 것:
    버튼   transition duration-150 hover:opacity-60 active:scale-90
    하트   liked 일 때만  animate-in zoom-in-50 duration-200

  브라우저 실측(계산값이라 숨은 탭에서도 유효):
    안 눌림   animationName: none    / 버튼 transitionDuration 0.15s
    눌림      animationName: enter   / animationDuration 0.2s

11-2. ⚠️⚠️⚠️ 숨은 탭 함정 3차 — 이번엔 "멈춘 트랜지션" 이 색을 거짓말했다

     배치(offsetWidth·clientWidth)          숨은 탭에서도 참
     계산된 정적 값(animationName·duration)  참
     전환 중인 값(색·transform·rect)         거짓 — 시작값에 멈춰 있다

12. Step 7 — 어두운 화면에 남은 어긋남 (--ring · 두 빨강)
--------------------------------------------------------------------------------

  들여온 판이 :root 와 .dark 에 자기 값을 들고 있었다.

                    :root                      .dark
    --ring          oklch(0.708 0 0) 회색       oklch(0.556 0 0) 회색
    --destructive   oklch(0.577 .245 27.3)     oklch(0.704 .191 22.2)
    (우리 --color-danger 는 양쪽 다 oklch(64.1% 0.2 20.5) 한 값)

  ⚠️ --ring 은 우리 포커스 색(brand)과 아무 관계가 없었는데, 화면 전체에 걸려 있었다.

    빌드 CSS 에서 실제로 이렇게 나온다:
      *{border-color:var(--border);outline-color:var(--ring)}
      *{outline-color:color-mix(in oklab, var(--ring) 50%, transparent)}

    globals.css 의 @layer base { * { @apply border-border outline-ring/50 } } 이 그것이다.
    var(--ring) 5곳 · var(--destructive) 22곳.

  ⚠️ E-2 회수 — --color-ring · --color-destructive 는 빌드 CSS 에 **0건**이다.
     이 이름들이 @theme inline 안에 있어서다(값이 쓰는 자리에 박히고 :root 에 안 남는다).
     E-4 의 --breakpoint-* 가 0건이던 것과 결과는 같지만 이유가 다르다.
       E-4: 미디어 조건이 var() 를 못 읽어서
       E-7: @theme inline 이라 원래 안 남는 것
     getComputedStyle 로 --color-ring 을 읽으면 빈 문자열이 나온다.

  고침(E-6 에서 --card 를 이은 것과 같은 방식):
    :root  --ring: var(--color-brand);  --destructive: var(--color-danger);
    .dark  두 줄 삭제
