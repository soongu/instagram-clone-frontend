1. ⚠️⚠️ 컨테이너를 세우는 줄은 E-6 에서 이미 들어와 있었다 — 묻는 줄만 0건이었다
--------------------------------------------------------------------------------

  E-6 이 복사해 온 card.tsx:30 에 @container/card-header 가 있다.
  빌드 CSS 에서:

    .\@container\/card-header{container:card-header/inline-size}

  그런데 @container ( ... ) 조건절은 파일 전체에 **0건** 이었다.
    grep -o "@container[^{]*" dist/assets/*.css | sort | uniq -c
      1 @container\/card-header      ← 통을 세우는 줄(클래스)
                                     ← 묻는 줄은 없음

  => 통은 세워져 있는데 아무도 묻지 않는 상태. E-7 의 출발점이 여기다.

  우리 피드는 그때까지 창에게 물었다:
    @media (width>=62.25rem)         ← --breakpoint-2col: 62.25rem


2. ⚠️⚠️⚠️ E-4 회수가 두 겹이다 — 조건엔 var() 를 못 쓰는데 :root 엔 이름이 있다
--------------------------------------------------------------------------------

  E-4 의 결론: --breakpoint-* 는 빌드 CSS 의 :root 에 0건.
              미디어 쿼리 조건은 var() 를 못 읽기 때문.

  컨테이너 쪽도 똑같다. --container-2col: 60.25rem 을 선언하고 @2col: 를 쓰면:

    @container (width>=60.25rem)     ← 값이 박혀서 나온다
    grep -c "--container-2col" → 0   ← :root 에 없다

  그런데 여기서 갈린다 — --container-sm 과 --container-lg 는 :root 에 **있다**.

    :root  … --container-sm:24rem;--container-lg:32rem; …
    @media (width>=40rem){ .sm\:max-w-lg{max-width:var(--container-lg)} }
                                                       ^^^^^^^^^^^^^^^^

  => --container-* 는 한 이름으로 두 가지 일을 한다.
       조건으로 쓰일 때(@sm: · @2col:)  → 값이 박히고 :root 에 안 남는다
       값으로 쓰일 때(max-w-sm · max-w-lg) → var() 로 읽으므로 :root 에 남는다

     E-4 를 "토큰은 조건에 못 쓰니까 :root 에 안 나온다" 로 외운 학생은
     :root 에서 --container-sm 을 보고 정확히 틀린 결론을 낸다.
     남아 있는 이유가 조건이 아니라 **폭 값** 이기 때문이다.


3. ⚠️⚠️ 토큰 이름을 옮기면 다른 곳의 2col: 이 경고 없이 죽는다
--------------------------------------------------------------------------------

  --breakpoint-2col 을 --container-2col 로 바꾸는 순간, @ 가 없는 2col: 은
  전부 존재하지 않는 변형이 된다. 그런데:

    · 빌드는 성공한다
    · 경고가 하나도 안 나온다   (npm run build 2>&1 | grep -i warn → 없음)
    · 클래스 문자열은 JSX 에도 DOM 에도 그대로 남는다
    · 빌드 CSS 에서 규칙만 0건이 된다

      2col\:mb-0            → 0건
      2col\:max-w-\[470px\] → 0건

  실제로 죽었던 두 곳:
    PostCard    mb-6 2col:mb-0            두 열일 때 카드 아래 여백이 안 지워짐
    SignUpForm  p-4 2col:max-w-[470px]    통이 넓어지면 폼이 따라 늘어남

  둘 다 밝은 화면·좁은 창에서는 안 드러난다. E-5 의 "확인은 전부 초록인데
  화면이 깨졌다" · E-6 의 "밝은 화면에선 두 판이 똑같다" 와 같은 계열.

  ⚠️ 검증 중 내가 낸 실수 — grep 이스케이프를 잘못 써서
     @2col\:max-w-\[470px\] 를 "0건" 으로 읽고 살아나지 않았다고 판단할 뻔했다.
     실제로는 5개 규칙이 전부 있었다. 셸 인용부호를 거치는 패턴은
     결과가 0 일 때 한 번 더 다른 방법으로 확인할 것.

  가드: e7-visual-polish.test.tsx 의
        "창을 보던 2col: 이 화면 어디에도 안 남았다"
        → expect(html).not.toMatch(/(?<!@)2col:/)
        SignUpForm 을 일부러 되돌려 실제로 잡히는 것 확인함.

5. ⚠️⚠️ main 이 "재는 상자" 이면서 동시에 "폭 상한" 일 수는 없다
--------------------------------------------------------------------------------

  E-6 까지 main 은 이랬다:
    mx-auto max-w-[470px] py-4 sm:px-4 2col:max-w-[996px]

  창 조건을 통 조건으로 바꾸려면 main 이 통이 돼야 하는데, main 이 470px 로
  묶여 있으면 통 폭이 964 에 영영 못 닿는다(자기가 자기 조건을 막는다).
  그래서 상한을 걷고 max-w-[996px] 하나만 남겼다.

  그러자 1열일 때 카드가 통 폭까지 늘어났다:
    창 980px → main 980 → 카드 948px   (원래는 470px)
    회원가입 폼도 같이 늘어남
    카드가 948px 이라 @lg:(512px) 이 카드 안에서도 걸려 아바타가 44px 로 커짐

  ⚠️ 단위 테스트는 전부 초록이었다. className 문자열만 보기 때문이다.
     브라우저를 열어야만 보이는 종류의 회귀 — E-5·E-6 과 같은 계열.

  고침: 상한을 카드와 폼이 각자 갖는다.
    Card       @container mx-auto mb-6 max-w-[470px] @2col:mb-0
    SignUpForm ... p-4 max-w-[470px]        ← @2col: 조건이 하나 없어졌다
                                              (통이 넓어져도 늘어날 일이 없어짐)


6. 컨테이너 쿼리 실측 — 창은 내내 784px 이었다
--------------------------------------------------------------------------------

  창을 한 번도 안 건드리고 main 의 폭만 바꿔가며 쟀다.
  (컨테이너 쿼리는 창이 아니라 그 상자의 폭을 보므로 이렇게 재는 것이 정확하다.)

    통 폭     피드            칸              카드     아바타
    ------   -------------   -------------   ------   ------
    963px    block (1열)     —               470px    32px
    964px    grid  (2열)     470px 470px     470px    32px     ← 임계 60.25rem 정확
    1200px   grid  (2열)     588px 588px     470px    32px     ← 칸은 넓어져도 카드는 470

  => 창은 784px 로 고정이었는데 피드가 2열이 됐다.
     미디어 쿼리로는 절대 만들 수 없는 상태다. 이것이 Step 2·3 의 증거다.

  모달 쪽 (zoom 으로 유효 뷰포트를 넓혀 실제 넓은 화면을 재현):
    dialog offsetWidth   896px   (= sm:max-w-4xl)
    dialog 컨텐츠 폭      864px
    안쪽 grid            422px 422px     ← @3xl(48rem=768px) 걸림 → 사진 왼쪽·글 오른쪽
    아바타               44px            ← @lg(32rem=512px) 걸림
    사진                 422px

  같은 글자 @lg:size-11 이 카드(470px)에서는 32px, 모달(864px)에서는 44px.


7. ⚠️⚠️⚠️ 백그라운드 탭이 또 물었다 — 이번엔 "멈춘 애니메이션" 으로
--------------------------------------------------------------------------------

  document.visibilityState 는 이 세션 내내 "hidden" 이었다.
  resize_window 도 먹지 않아 창은 784px 에 고정.

  모달 아바타를 재니 41.8px 이 나왔다. 44 도 32 도 아닌 값이다.

    getComputedStyle(dlg).transform → matrix3d(0.95, 0, 0, 0, 0, 0.95, ...)

  열리는 애니메이션(data-open:zoom-in-95)이 0.95 에서 멈춰 있었다.
  rAF 가 안 도니 애니메이션이 끝나지 않고, getBoundingClientRect 는
  변형이 적용된 상자를 돌려준다.  44 × 0.95 = 41.8.

  ⚠️ 갈라 쓸 것:
     getBoundingClientRect()  변형이 반영된다 → 애니메이션 중이면 오염
     offsetWidth / clientWidth 변형을 무시한다 → 배치 검증에는 이쪽

  ⚠️ 배치(geometry)는 숨은 탭에서도 동기적으로 계산되므로 위 6번 수치는 유효하다.
     시간·프레임에 기대는 것(전환·포커스 이동·애니메이션 완료)만 못 믿는다.
     Step 6(마이크로 인터랙션) 측정은 탭을 앞으로 가져온 뒤에 다시 해야 한다.
