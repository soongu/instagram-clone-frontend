5. ⚠️⚠️ @custom-variant — E-4 가 예고한 것과 shadcn 이 쓴 것이 다르다
-----------------------------------------------------------------------

  E4-lecture.md:855  @custom-variant dark (&:where(.dark, .dark *));   <- 문서 형태
  shadcn 이 써넣은 것 @custom-variant dark (&:is(.dark *));            <- 실물

  둘의 차이를 브라우저에서 직접 갈라 봤다:

    (가) .dark 를 단 요소 **자신**
         :is(.dark *)             안 걸림   (자손만 본다)
         :where(.dark, .dark *)   걸림      (자기 자신도 목록에 있다)

    (나) 자손 — 둘 다 걸림

    (다) 특정도 — 뒤에 오는 같은 급 클래스 규칙과 겨루면
         :is    이김   ( :is 는 인자 중 가장 센 것의 특정도를 가져온다 → (0,2,0) )
         :where 짐     ( :where 는 항상 0 → (0,1,0) 동률 → 나중 것이 이김 )

  => shadcn 이 :is 를 쓰는 이유가 (다)다. dark: 유틸리티가 평소 유틸리티에
     특정도로 이기게 하려는 것.
  ⚠️ E-4 는 문서 형태를 옮겨 적었고 그건 그때 실행 검증까지 했다(E-4 채증 13번).
     둘 다 동작하지만 같지 않다. 교안에서 "지난 시간에 본 그 줄" 이라고 뭉뚱그리면
     학생이 자기 파일에서 다른 글자를 보고 혼란스러워한다.

  ⚠️ 우리 앱은 dark: 유틸리티를 0개 쓴다(e4 테스트가 not.toMatch(/dark:/) 로 강제).
     그래서 이 변형 줄은 **지금은 아무 일도 안 한다**. 실제로 일하는 것은 6번의
     .dark 규칙이다. 변형이 일하기 시작하는 것은 shadcn 컴포넌트가 들어오는 다음 강의.


6. 조건을 옮겼다 — 값은 한 개도 안 바꿈
-----------------------------------------

  before  @media (prefers-color-scheme: dark) { :root { --color-*: ... } }
  after   .dark { --color-*: ... }

  빌드 CSS 확인:
    .dark{--color-canvas:oklch(0% 0 none);--color-surface:oklch(18.2% 0 none);
          --color-ink:oklch(97% 0 none);--color-faint:oklch(73.2% 0 none);
          --color-subtle:oklch(83% 0 none);--color-line:oklch(33.3% 0 none);
          --color-line-soft:oklch(26.9% 0 none)}
    "prefers-color-scheme" 등장 횟수 **0**
    CSS 17,855 → 17,819 B (−36, @media 감싸개가 빠진 만큼)

  우리 .dark 블록 바로 뒤에 shadcn 의 .dark 블록이 따로 온다. 겹치는 속성이 없어
  둘 다 산다(우리는 --color-*, 저쪽은 --background 계열).

  손으로 붙였다 뗀 확인 (className 은 한 글자도 안 고쳤다):
    표시 없음 → body 0.985 / 카드 1.0     / 테두리 0.891 / faint 0.647
    .dark 붙임 → body 0     / 카드 0.182  / 테두리 0.333 / faint 0.732
    다시 뗌   → 처음 값과 완전히 동일
  값은 E-4 팔레트 그대로다.


7. 세 갈래 고르개 — '시스템' 은 "안 고르겠다" 로 돌아올 길
-----------------------------------------------------------

  고른 것(choice: light|dark|system)과 실제로 그릴 것(resolved: light|dark)을
  나눠 뒀다. 시스템을 고른 사람만 matchMedia 알림을 따라간다.

  브라우저 실측 (OS 는 라이트):
    처음        표시 (없음)  눌린 것 시스템   저장값 null
    어둡게 클릭  표시 dark    눌린 것 어둡게   저장값 "dark"
    밝게 클릭    표시 (없음)  눌린 것 밝게     저장값 "light"
    시스템 클릭  표시 (없음)  눌린 것 시스템   저장값 "system"

  고른 칸 색은 bg-ink text-canvas 로 뒀다 — E-4 가 토스트에서 쓴 그 짝이라
  다크에서 저절로 뒤집힌다(다크에서 잰 값: 배경 oklch(0.97) 글자 oklch(0)).

  ⚠️ jsdom 에는 matchMedia 가 **아예 없다**(typeof → undefined). App 을 렌더하는
     테스트가 15개쯤 되므로 test-setup.ts 에 "시스템은 밝게" 로 답하는 최소 stub 을
     깔았다. 시스템이 바뀌는 상황은 그 테스트가 vi.stubGlobal 로 자기 것을 끼운다.
  ⚠️ matchMedia 리스너가 부르는 setState 는 act() 밖이라 안 흘러간다.
     await act(async () => system.change(true)) 로 감싸야 통과한다.
     (production 버그가 아니라 테스트 하네스 문제 — 브라우저에서는 잘 돈다.)
  ⚠️ App 머리말에 고르개가 붙어 b3-use-like-toggle 의 "글자 하나 안 다르다" 비교가
     깨진다. B-5 가 withoutSignUpSection 을 만든 선례대로 withoutThemeToggle 추가.
