5. ★ 남은 숙제 (1) 해결 — INP 의 10x/20x 역전은 단발 노이즈였다
------------------------------------------------------------------
각 배율 5회씩 · 회차당 하트 10번 · 전부 「믿을 수 있는 5/5회」

  CPU     중앙값     전체                        입력지연 / 처리 / 그리기 (평균)
  1x       32ms     [32, 32, 32, 40, 248]        0.3 / 0.3 / 24.5
  4x       32ms     [32, 32, 32, 32, 32]         1.8 / 1.3 / 21.0
  10x      56ms     [48, 48, 56, 56, 64]         6.2 / 3.5 / 31.8
  20x     112ms     [104, 112, 112, 112, 112]   14.2 / 8.5 / 51.7

★ 핸드오프의 「10x 224ms / 20x 144ms 역전」은 재현되지 않는다.
  5회씩 재니 32 → 32 → 56 → 112 로 단조 증가한다. 단발 측정이 만든 착시였다.

★★ 1x 의 248ms 가 이 회차의 교보재다.
  같은 조건 5회 중 네 번은 32~40 인데 한 번이 248 이다.
  이유는 INP 의 정의 자체 — 상호작용이 50건 미만이면 **가장 나쁜 것 하나**가 곧 INP 다.
  (그 회차의 상호작용별: [248, 32, 24, 24, 24, 24, 24, 24, 24, 24] — 아홉 개는 멀쩡하다)
  ⇒ "한 번 재고 끝내면 안 된다" 를 우리 숫자로 말할 수 있다.

★★★ 3분해가 왜 그런지까지 답한다 — 어느 배율에서든 그리기가 가장 크다.
  20배로 조여도 우리 코드가 도는 시간(처리)은 8.5ms 다.
  INP 가 낮은 이유는 우리 코드가 빨라서가 아니라 **할 일이 거의 없어서**이고,
  그리기는 화면이 다음 프레임을 그리는 시간이라 CPU 를 조여도 크게 안 는다.
  ⇒ 20배 느린 기기에서도 112ms 로 기준(200ms) 이하다.
