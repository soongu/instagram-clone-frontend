2. remotePatterns 한 줄
-----------------------
  images: { remotePatterns: [new URL('https://picsum.photos/seed/**')] }

  최적화 엔드포인트 실측 (같은 원본 640x640):
    picsum 원본 직접                          image/jpeg   74,427 B
    /_next/image w=640 q=75  (Accept 없음)    image/jpeg   65,557 B
    /_next/image w=640 q=75  (Accept avif)    image/webp   64,182 B
    /_next/image w=384 q=75  (Accept avif)    image/webp   27,102 B   ← 원본의 36%

  ⇒ 브라우저가 보낸 Accept 로 포맷이 갈리고, 필요한 폭만큼만 다시 만든다.

  qualities 는 Next 16 에서 잠겨 있다 (미설정 = [75] 만 허용):
    q=75   → 200
    q=50   → 400  "q" parameter (quality) of 50 is not allowed
    q=100  → 400  "q" parameter (quality) of 100 is not allowed
  문서: "This field is required starting with Next.js 16 because unrestricted access
        could allow malicious actors to optimize more qualities than you intended."
  maximumRedirects 기본값이 무제한 → 3 으로 바뀐 것도 같은 결.


3. 밀림 실측 — 실물 피드에서 잰 숫자
------------------------------------
  측정 방법: 실제 피드 화면에서 <img> 의 src 를 뗐다 붙이며 문서/요소 위치를 잰다.
  창 1853x1031 · 컨테이너 폭 494px · 사진 원본 640x640.

    (A) 그냥 <img src={post.imageUrl} alt={...} />      — 폭·높이 안 알려줌
        사진 없을 때 첫 사진 자리 높이      24 px   (alt 글자 한 줄)
        사진 왔을 때                       494 px
        문서 높이                        1,686 → 6,390 px
        열 번째 게시물 위치              1,524 → 5,757 px
        ⇒ 밀린 높이 4,233 px

    (B) <Image ... width={640} height={640} className="h-auto w-full" />
        사진 없을 때 첫 사진 자리 높이     494 px   ← 이미 잡혀 있다
        사진 왔을 때                       494 px
        문서 높이                        6,456 → 6,456 px
        열 번째 게시물 위치              5,817 → 5,817 px
        ⇒ 밀린 높이 0 px

  ⚠️ CLS 지표(PerformanceObserver 'layout-shift')로는 못 쟀다 — 탭이 hidden 이면
     layout-shift 엔트리가 아예 안 쌓인다(shiftEvents 0). 게다가 처음엔 레이아웃 자체가
     안 돌아 docHeight 가 1,289 로 나왔다. Chrome 활성화 뒤 6,390 으로 정상화.
     (이 맥의 앱 이름은 "Google Chrome" 이 아니라 "Google Chrome 2" — D-8 때 AppleScript 가
      5회 실패한 이유가 이것일 수 있다.)


4. LCP 힌트 — priority 는 Next 16 에서 폐기됐다
-----------------------------------------------
  Next 가 dev 콘솔에 스스로 말해준다:
    [browser] Image with src "..." was detected as the Largest Contentful Paint (LCP).
              Please add the `loading="eager"` property if this image is above the fold.
  → priority 가 아니라 loading="eager" 를 부른다.

  문서(16.3.1, lastUpdated 2026-08-18):
    "Starting with Next.js 16, the `priority` property has been deprecated in favor of
     the `preload` property in order to make the behavior clear."
    "In most cases, you should use `loading=\"eager\"` or `fetchPriority=\"high\"`
     instead of `preload`."

  렌더 결과 실측 (첫 사진 기준):
                        <img loading>     head <link rel=preload as=image>
    아무것도 안 줌        lazy              0
    priority (폐기)       (없음)            1
    preload (현행)        (없음)            1
    loading="eager"       eager             1

  ⇒ priority 는 아직 동작하고 tsc·eslint·dev 로그 어디에서도 경고가 없다.
    조용히 낡는 자리라 grep 게이트 후보.

  loading={index === 0 ? 'eager' : 'lazy'} 로 고치면 LCP 경고가 사라진다(재현 확인).
  eslint 는 그냥 <img> 를 쓰면 말은 해준다 — 단 warning 이라 exit 0:
    warning  Using `<img>` could result in slower LCP and higher bandwidth...
             @next/next/no-img-element

6. Metadata API
---------------
  layout.tsx 의 정적 metadata 는 모든 화면에 같은 제목을 준다.
  [username]/page.tsx 에 generateMetadata 를 두면 주소마다 갈린다:

    /            <title>인스타그램 클론</title>
    /explore     <title>인스타그램 클론</title>
    /minji       <title>@minji · 인스타그램 클론</title>
                 <meta name="description" content="팔로워 8500명"/>

  openGraph 키를 더하면:
    <meta property="og:title" content="@minji"/>
    <meta property="og:description" content="팔로워 8500명"/>
    <meta property="og:image" content="https://picsum.photos/seed/minji/64/64"/>
    <meta property="og:image:width" content="64"/> <meta property="og:image:height" content="64"/>
  루트(/)에는 og 태그가 0 건 — 정적 metadata 에 openGraph 를 안 넣었기 때문.

  ⚠️ cacheComponents: true 와 충돌하지 않는다. 반례로 generateMetadata 가
    굳지 않는 함수(fetchPostsByUsername — 'use cache' 없음)를 부르게 해봤는데도
    build exit 0 이고 라우트 표도 ◐ 그대로였다. metadata 는 캐시 규칙 밖이다.
  dev 로그에 generate-params 항목이 새로 보인다:
    GET /minji 200 in 2.7s (next.js: 813ms, proxy.ts: 408ms, generate-params: 198ms,
                            application-code: 1312ms)


7. output: 'standalone' — 그냥 띄우면 화면이 벌거벗는다
-------------------------------------------------------
  next.config 에 output: 'standalone' 한 줄. build exit 0.

  산출물 구조 (npm workspaces 모노레포라 한 겹 더 들어간다):
    .next/standalone/
      node_modules/            (sharp·next·react 등 실행에 필요한 것만)
      apps/web-next/
        .next/                 (server·manifest — static 은 없다)
        package.json
        server.js              ← 여기 있다. standalone 뿌리가 아니다

  크기:  node_modules 684 MB  →  .next/standalone 50 MB

  그대로 `node apps/web-next/server.js` 로 띄우면:
    GET /                        200  (23,168 B)
    GET /_next/static/...css     404
    GET /_next/static/...js      404
  ⇒ 페이지는 200 인데 스타일도 없고 버튼도 안 눌린다. 200 이 정상이 아니다.

  .next/static 을 standalone 안으로 복사하고 서버를 다시 띄우면 CSS·JS 둘 다 200.
  (복사만 하고 재시작을 안 하면 계속 404 — 부팅 시점에 목록을 잡는다.)

  ⚠️ public/next.svg 가 404 인 것은 standalone 탓이 아니다 — dev(3100)에서도 404 다.
    proxy matcher 가 물어서 api-stub 에 "next.svg 라는 사람 있나" 를 묻고 404 를 받는다.

11. 교안 집필 중 새로 드러난 것 (Step 8 · 과제 4)
--------------------------------------------------
  metadata 물려받기는 "키 하나 단위" 다.
    /explore 가 openGraph 를 안 줄 때   → 루트의 og:title·og:description·og:type 셋 다 내려온다
    /explore 가 openGraph 를 줄 때      → og:type 이 사라진다 (안쪽 항목끼리 안 섞인다)
  ⇒ 아래에서 openGraph 를 주면 껍데기 것 중 필요한 항목을 다시 적어야 한다.

  og:image 는 remotePatterns 검사를 안 거친다.
    'https://example.com/no-such-image.png' (404 · 허락 목록 밖 호스트)를 넣어도
    tsc 0 · eslint 0 · build exit 0 · GET /minji 200 · dev 로그 아무 말 없음.
    /_next/image 를 안 지나가니 목록과 무관하다 — 그냥 문자열이다.

  ⚠️ 과제 초안이 틀렸다 — picsum.photos 는 어떤 seed 든 200 을 준다.
    'seed/이런건없어요' 로는 안 깨진다(200). 진짜 404 를 쓰려면
    'picsum.photos/no-such-path.png'(404) 나 다른 호스트를 써야 한다.
    → 과제 지문을 "실제로 404 가 나는 주소 · 허락 목록 밖 호스트" 로 고쳤다.

  next/font 인용 정정 — 초안이 src: local("Apple SD Gothic Neo") 로 적었는데
    실제 생성물은 src: local(Arial) 이다. font-family 도 따옴표가 없다.
    (지어낸 값이 대조에서 잡힌 자리)
