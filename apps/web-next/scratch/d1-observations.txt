[1] 갓 만든 앱은 타입 검사를 통과하지 못한다 (빌드 전)
----------------------------------------------------------------
create-next-app 직후, next 를 한 번도 안 돌린 상태:

  $ ls -d .next          → 없음
  $ npx tsc --noEmit
  app/layout.tsx(20,50): error TS2304: Cannot find name 'LayoutProps'.
  exit=1

next build 를 한 번 돌린 뒤:

  $ npx tsc --noEmit
  exit=0

원인: LayoutProps 는 손으로 쓴 타입이 아니라 .next/types/routes.d.ts 에
declare global 로 생성되는 타입이다. Next 가 app/ 폴더를 읽어야 생긴다.
→ 저장소를 새로 받은 사람은 npm install 만으로는 타입 검사가 안 통과한다.

[2] 폴더를 만들면 타입이 자란다 (측정)
----------------------------------------------------------------
.next/types/routes.d.ts 의 AppRoutes 유니온 실측:

  app/page.tsx 만 있을 때
    type AppRoutes = "/"
    interface ParamMap { "/": {} }

  app/explore/page.tsx + app/[username]/page.tsx 를 추가한 뒤
    type AppRoutes = "/" | "/[username]" | "/explore"
    interface ParamMap {
      "/": {}
      "/[username]": { "username": string; }
      "/explore": {}
    }

폴더 이름이 주소가 되는 것을 넘어, 폴더 이름이 그대로 타입이 된다.
대괄호 칸은 ParamMap 에 { username: string } 으로 정확히 박힌다.

[3] C-2 와의 대조 (같은 일, 다른 타입 강도)
----------------------------------------------------------------
React Router 8  useParams()            → string | undefined
Next.js 16      PageProps<'/[username]'>.params → Promise<{ username: string }>

라우터는 주소를 "배열에 적은 값" 으로 받으므로 컴파일 시점에 알 수 없다.
Next 는 주소가 "폴더" 라 파일 시스템을 읽어 타입을 만들 수 있다.
→ 차이는 라이브러리 성능이 아니라 주소를 어디에 적었느냐다.

주의: params 가 Promise 다 (Next 16 async 요청 API). D-4 소관이므로
D-1 에서는 "왜 기다리는지는 나중에" 한 줄로만 짚는다.
