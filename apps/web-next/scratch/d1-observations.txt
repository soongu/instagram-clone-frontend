[2] 폴더를 만들면 타입이 자란다 (측정)
----------------------------------------------------------------
.next/types/routes.d.ts 의 AppRoutes 유니온 실측:

  app/page.tsx 만 있을 때
    type AppRoutes = "/"
    interface ParamMap { "/": {} }

  app/explore/page.tsx + app/[username]/page.tsx 를 추가한 뒤
    type AppRoutes = "/" | "/[username]" | "/explore"
    interface ParamMap {
      "/": {}
      "/[username]": { "username": string; }
      "/explore": {}
    }

폴더 이름이 주소가 되는 것을 넘어, 폴더 이름이 그대로 타입이 된다.
대괄호 칸은 ParamMap 에 { username: string } 으로 정확히 박힌다.

[3] C-2 와의 대조 (같은 일, 다른 타입 강도)
----------------------------------------------------------------
React Router 8  useParams()            → string | undefined
Next.js 16      PageProps<'/[username]'>.params → Promise<{ username: string }>

라우터는 주소를 "배열에 적은 값" 으로 받으므로 컴파일 시점에 알 수 없다.
Next 는 주소가 "폴더" 라 파일 시스템을 읽어 타입을 만들 수 있다.
→ 차이는 라이브러리 성능이 아니라 주소를 어디에 적었느냐다.

주의: params 가 Promise 다 (Next 16 async 요청 API). D-4 소관이므로
D-1 에서는 "왜 기다리는지는 나중에" 한 줄로만 짚는다.

[7] Step 5 채증 — 생성된 타입이 실제로 막아주는가 (세 탐침, 2026-08-18)
----------------------------------------------------------------
app/[username]/page.tsx 를 일부러 틀리게 고쳐 tsc --noEmit 을 돌렸다.

A. 없는 주소를 PageProps 에 넣기 → PageProps<'/profile/[username]'>
   TS2344: Type '"/profile/[username]"' does not satisfy the constraint 'AppRoutes'.
   TS2339: Property 'username' does not exist on type 'unknown'.
   → 폴더에 없는 주소는 타입 인자로 못 쓴다.

B. 없는 칸 이름 꺼내기 → const { userName } = await params;
   TS2339: Property 'userName' does not exist on type '{ username: string; }'.
   → 에러 메시지가 실제로 있는 칸의 모양을 그대로 보여준다.

C. await 빼기 → const { username } = params;
   TS2339: Property 'username' does not exist on type 'Promise<{ username: string; }>'.
   → 기다려야 한다는 사실을 타입이 직접 말해준다. 조용히 undefined 가 되지 않는다.

셋 다 원복 후 tsc 0.

★ C-2 정전과 정면 대비:
   React Router 8   useParams()      → string | undefined
                    useLoaderData()  → any  (틀려도 통과시킨다)
   Next.js 16       params           → Promise<{ username: string }>
                    위 세 실수가 전부 컴파일에서 막힌다

라이브러리 품질 차이가 아니라 주소를 어디에 적었느냐의 차이다.
배열에 적은 주소는 컴파일 시점에 읽을 수 없고, 폴더로 적은 주소는 읽을 수 있다.

⚠️⚠️ 교안 쓸 때 반드시 주의 — 붙어 있는 글자가 HTML 에서는 안 붙어 있다
----------------------------------------------------------------
React 는 서버에서 그릴 때 이웃한 텍스트 노드 사이에 주석을 끼워 넣는다.

  화면:  @jaehoon              HTML:  @<!-- -->jaehoon
  화면:  게시물 3               HTML:  게시물 <!-- -->3
  화면:  좋아요 1240            HTML:  좋아요 <!-- -->1240

→ 학생에게 "소스 보기에서 @jaehoon 을 찾아보세요" 라고 쓰면 0건이 나와
  실패한 줄 안다. 반드시 **한 표현식이 통째로 만드는 문자열**을 찾게 한다.

  ✅ 안전:  "오늘 한강 노을이 미쳤다"  ({post.content} 하나가 통째로)
  ❌ 위험:  "@jaehoon" · "좋아요 1240" · "게시물 3"  (글자+값이 붙은 것)
