3절. 서버 액션 CSRF — G-5 8절 재현 (결론 일치)
----------------------------------------------
[/minji 팔로우 · -F(multipart) 로 제출 · 로그인 쿠키 포함]

  우리 Origin    curl 200   쓰기 도달 1건   POST /api/users/minji/follow
  남의 Origin    curl 500   쓰기 도달 0건   ← 막힘
  Origin 없음    curl 200   쓰기 도달 2건   ← 통과

서버 로그(원문 그대로):
  `x-forwarded-host` header with value `localhost:3000` does not match `origin`
  header with value `evil.example.com` from a forwarded Server Actions request.
  Aborting the action.
  ⚠ Missing `origin` header from a forwarded Server Actions request.   ← 없으면 경고만

⚠ 도달 «건수» 는 G-5 8절(2/0/1)과 다르다(1/0/2). 첫 호출에 백엔드 출입증 발급
  (POST /api/auth/login)이 끼는지에 따라 갈리고, 재시도로 2건이 되기도 한다.
  => 교안은 숫자를 쓰지 않고 **도달했나 / 0건인가** 만 쓴다(G-5 14절 선례 —
     워밍업 의존 수치는 기제만 싣는다).

판별되는 것: 남의 Origin 만 500 이고 도달 0. 나머지 둘은 실행된다.

5절. 🆕 신규 측정 — G-4 페이로드가 실제로 막힌다 (G-5 채증에 없던 것)
---------------------------------------------------------------------
G-5 16절이 확인한 것은 «탐침 페이지의 인라인 script» 였고, **G-4 의 진짜 페이로드가
댓글 경로로 들어왔을 때** 는 아무도 안 재봤다. 그래서 새로 쟀다.

[준비] api-stub 에 G-4 페이로드를 minji 이름으로 저장:
  <script>document.title = "털렸습니다"</script>사진 좋네요

[A] 살균 켠 현재 상태 (= G-4 종료 시점의 앱)
  서버가 보낸 HTML: document.title 0건 · '털렸습니다' 0건 · '사진 좋네요' 1건
  => DOMPurify 가 태그를 통째로 지운다. CSP 가 나설 일이 없다.

[B] 살균에 구멍이 뚫렸다고 가정 (CommentSection 에서 sanitizeComment 를 임시 제거)
  서버가 보낸 HTML: document.title 1건 · '털렸습니다' 1건   ← 태그가 그대로 실려 나간다
  응답 헤더: content-security-policy: default-src 'self'; script-src 'self' 'nonce-…'

  브라우저에서(로그인 후 새로고침 · 2.5초 대기):
    document.title            "인스타그램 클론"   ← **안 바뀌었다. 실행 안 됨**
    DOM 안 그 <script> 개수    1
    그 태그의 내용             document.title = "털렸습니다"
    그 태그의 nonce            null                ← 번호표가 없어서 거절됐다

★ 결론: **CSP 는 구멍을 메우지 않는다. 태그는 DOM 에 그대로 있고 실행만 막힌다.**
  커리큘럼 G-6 행의 문장이 실측으로 확인됐다.

⚠️⚠️ 내가 하마터면 틀리게 쓸 뻔한 것 — «화면에 그대로 남아 있다» 의 뜻
  li.textContent 로 읽으면 `@minjidocument.title = "털렸습니다"사진 좋네요` 가 나와서
  **공격 코드가 화면에 글자로 보이는 것처럼** 읽힌다. 실제로는:
    getComputedStyle(script).display === 'none'
    보이는 글자만 다시 세면            '사진 좋네요'
  => 남아 있는 곳은 **DOM** 이지 화면이 아니다. textContent 는 script 안쪽까지
     읽어주기 때문에 생긴 착시다. 교안은 «DOM 에 남아 있다» 로 정확히 쓴다.
     (D-7 canon 은 숨은 탭에서 innerText 대신 textContent 를 쓰라고 했는데,
      **바로 그 textContent 가 여기서는 거짓 그림을 준다** — 상황마다 맞는 자가 다르다.)

⚠️ 콘솔 위반 기록은 **확인하지 못했다.** read_console_messages 가 CSP 위반을 0건으로
   보고했는데, 탐침(console.error 직접 호출)을 심어보니 그 탐침은 잡힌다 —
   단 출처가 `chrome-extension://…installHook.js` 다. 즉 이 도구가 잡는 것은
   **확장 세계를 거친 console 호출**이고, 브라우저가 스스로 내는 CSP 위반 보고를
   잡는다는 증거는 없다. 탐침이 «잡히는 것이 잡히는지» 를 확인한 게 아니라
   **엉뚱한 것을 확인했다**(과목 캐논: 게이트가 「잘못 보는」 것은 침묵-감지로 못 잡는다).
   => 교안이 «콘솔에 위반이 남는다» 를 주장하려면 집필 단계에서 report-to 엔드포인트로
      서버 쪽 증거를 잡거나, 주장하지 않는다. 지금은 **미확인**으로 남긴다.

[복원] sanitizeComment 되돌림 · git status 깨끗 · git diff 0줄 ·

8절. 척추 — 네 Step 이 하나로 이어지는 자리
--------------------------------------------

11절. Step 4 — 문지기를 세운 뒤 (5조건)
----------------------------------------
[POST /api/profiles/revalidate?username=jaehoon]

  비밀 맞음(백엔드가 부르는 방식)   200  {"success":true,...}

★ 셋째 줄이 이 Step 의 결정타 — 로그인한 사람의 쿠키를 그대로 들고 가도 401 이다.
  이 문은 «누가 눌렀나» 를 묻는 문이 아니라 «어느 서버가 말하나» 를 묻는 문이라서다.

[비밀을 아예 안 정해둔 경우 — fail-closed 확인]

  => 주석에 쓴 «값을 안 정해두면 아무도 못 들어온다» 를 실행으로 확인했다
     (우리 예고도 실행으로 검증한다 — 과목 캐논).


12절. ⚠️⚠️ `expected === undefined` 검사는 그 자체로는 «중복»이다
------------------------------------------------------------------
빼고 재봤다(비밀도 안 정해둔 채):
  헤더 없음 / 헤더 아무거나  → **둘 다 401. 동작이 완전히 같다.**
  이유: headers.get() 은 없으면 `null` 을 주고 `null !== undefined` 가 참이라
        어차피 401 로 떨어진다.

=> 「이 줄이 없으면 뚫린다」로 쓰면 **가짜 결함**이다(C-4 canon). 안 쓴다.

★★ 그런데 진짜 함정은 다른 데 있었다 — `undefined` 가 위험한 게 아니라
   **누군가 그 `undefined` 를 «고치는» 순간 열린다.**

  const expected = process.env.REVALIDATE_SECRET ?? '';   // 흔한 «방어적» 수정
  (+ undefined 검사 제거 · 비밀 안 정해둠)

    헤더 없음          401
    **빈 값 헤더 하나   200**   ← 문이 활짝 열린다
                                 (`curl -H 'x-revalidate-secret;'`)

  빈 문자열끼리 같아져서 통과한다. 코드는 더 안전해 보이고, 빌드·타입·린트 전부 초록이고,
  평소처럼 쓰면 아무 일도 안 일어난다. **빈 헤더 하나를 보내볼 사람만 안다.**

=> 그래서 `expected === undefined` 를 **남긴다.** 근거는 «없으면 뚫린다» 가 아니라
   **«비밀이 없으면 아무도 못 들어온다» 를 코드가 말로 못 박아 두는 것**이다.
   그래야 나중에 누가 `?? ''` 로 «고칠» 때 그 줄이 먼저 눈에 걸린다.
   ⇒ 이 실측을 **과제**로 승격한다(학생이 `?? ''` 로 고쳐보고 빈 헤더를 보내보는 과제).

⚠️ 시간 일정 비교(timingSafeEqual)는 **안 넣었다** — 강의용 적정선을 넘고,
   이 회차의 주제(누가 부르는 문인가)에서 초점을 흐린다. 🙋 토글로 이름만 짚는다.

5절에서 read_console_messages 가 CSP 위반을 0건으로 보고했고, console.error 탐침은

[올바른 탐침] 주입한 «코드» 는 격리 세계라 CSP 를 안 받지만(G-5 7절),

  → 같은 위반을 read_console_messages 로 조회 → **0건**
