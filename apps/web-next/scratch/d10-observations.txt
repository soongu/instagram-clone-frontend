7. NEXT_PUBLIC_ 은 빌드 때 박힌다 (탐침 — 확인 후 원복, 흔적 0)
----------------------------------------------------------------
  HeaderNav(클라이언트 컴포넌트)에 process.env.NEXT_PUBLIC_PROBE 를 찍게 하고

    NEXT_PUBLIC_PROBE="빌드때값" npx next build
    NEXT_PUBLIC_PROBE="실행때값" node .next/standalone/apps/web-next/server.js

  화면에 뜬 것:  data-probe="true">빌드때값
  "빌드때값" 이 있는 곳:
    .next/static/chunks/20i6joh7skygl.js            ← 브라우저가 받아가는 파일
    .next/standalone/.../server/app/index.html      ← 미리 그려둔 HTML
    .../_not-found.html · .../explore.html
  "실행때값" 이 있는 곳:  0건

  대조 — 서버에서 읽는 값(config.ts)은 실행 때 값을 읽는다:
    API_BASE=... PORT=3500 node server.js → /jaehoon 200

  ⇒ 서버 값 = 띄울 때 정해짐(이미지 하나로 환경 여러 개 O)
     NEXT_PUBLIC_ = 빌드 때 정해짐(X) + JS 파일에 글자로 남아 누구나 열어볼 수 있다

9. 과제4 — .dockerignore 를 비우면
-----------------------------------
  (측정 결과는 이 절 아래에 이어 적는다)
  A(목록 있음) vs B(목록 비움) — 둘 다 --no-cache --progress=plain

                       A(있음)      B(비움)
    transferring ctx   31.32 kB     748.15 MB      ← 약 24,000배
    build real          38.62 s      49.44 s
    이미지              222 MB       249 MB        ← +27MB

  ★★★ 3번이 내 지문의 전제를 뒤집었다.
    초안은 "멀티스테이지라 마지막 단계가 새 공간에서 시작하므로 이미지는 그대로일 것"
    을 깔고 "예상과 다를 수 있다" 고만 썼는데, 실제로는 늘었고 이유가 훨씬 고약하다.

    /app            61.8 MB → 87.8 MB
    /app/node_modules  54.9 MB(11개) → 80.9 MB(12개)
    /app/node_modules/@img  35.3 MB → 61.3 MB

    @img 안 (A):  colour · sharp-libvips-linux-arm64 · sharp-libvips-linuxmusl-arm64
                  sharp-linux-arm64 · sharp-linuxmusl-arm64
    @img 안 (B):  위 전부 + sharp-darwin-arm64 · sharp-libvips-darwin-arm64
                  + sharp-wasm32   (그리고 최상위에 @emnapi 추가)

    ⇒ 호스트(macOS)의 node_modules 가 COPY . . 로 빌더에 들어갔고,
      standalone 추적기가 거기 있던 darwin 전용 바이너리까지 실행에 필요한 것으로
      집어 리눅스 이미지에 담았다. 그 컨테이너에서 영원히 못 도는 26MB 다.

    ★ Step 1 이 "제 맥에서 만든 폴더를 리눅스 서버에 복사하면 어떤 꾸러미는
      그대로 안 돌아갑니다" 라고 말한 그 일이 실제로 벌어진 것.
      안 담을 것 목록은 크기·시간만이 아니라 결과물의 정확성을 지킨다.

    ⚠️ 이것이 로컬 standalone 12개 vs 컨테이너 11개(@emnapi 차이)의 원인이기도 하다.
