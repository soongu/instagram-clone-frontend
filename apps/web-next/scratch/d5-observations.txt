3. ⚠️⚠️ 빌드가 fetch 를 부르는 조건 — D-4 기록의 누락된 전제
====================================================================

  .next 있는 채로 재빌드   exit 0 · stub 요청 0 건
  .next 지우고 클린 빌드    exit 0 · stub 요청 1 건  (GET /api/posts)

  api-stub 을 끈 상태에서:
  .next 있는 채로 빌드      exit 0          ← 프리렌더 결과를 재사용해 그냥 통과
  .next 지우고 클린 빌드     exit 1          ← ECONNREFUSED

                                             "Export encountered an error on /page: /"

  ★★★ D-4 채증은 "api-stub 없이 빌드하면 종료 코드 1" 이라고만 적었는데
      그것은 클린 빌드에서만 참이다. .next 가 있으면 조용히 통과한다.
      → 과제에서 이 실험을 시킬 때 rm -rf .next 를 반드시 함께 지시해야 한다.
        (안 그러면 학생 절반은 "저는 안 죽는데요" 가 된다)


4. Cache Components 를 켜면 — 플랜 단계 선행 검증
====================================================================

  next.config.ts 에 cacheComponents: true 한 줄

  빌드 헤더에 "- Cache Components enabled" 가 찍히고 exit 1.
  --debug-prerender 없이는 첫 라우트에서 끊긴다(prerenderEarlyExit).
  붙이면 전체 목록:

  Error: Route "/": uncached or runtime data during prerendering
      at get (lib/api.ts:16:26)
      at fetchPosts (lib/api.ts:32:10)
      at FeedList (app/components/FeedList.tsx:8:33)
      at HomePage (app/page.tsx:9:7)

  Error: Route "/[username]": uncached or runtime data during prerendering
  Error: Route "/[username]": URL data `usePathname()` in a Client Component
                              outside of <Suspense>   digest: CLIENT_HOOK_DYNAMIC
      at app/components/HeaderNav.tsx:17:20

  /explore 는 아무 에러도 안 났다 (파일 상수 = 예측 가능한 값).

  ★ 에러가 직접 말하는 세 갈래:
      [stream] <Suspense fallback={...}> 로 감싸라
      [cache]  "use cache" 로 캐시하라 (connection() 에는 안 통함)
      [block]  export const instant = false

  ★★ usePathname 은 / 에서는 안 막히고 /[username] 에서만 막힌다.
     주소를 빌드 때 아느냐가 갈랐다. (같은 컴포넌트 · 다른 판정)


5. 세 갈래를 실제로 골라본 결과
====================================================================

  [stream]  / 의 <FeedList/> 를 <Suspense> 로 감쌈        → / 통과
  [block]   /[username]/layout.tsx 에 instant = false     → /[username] 통과
  [cache]   lib/api.ts 의 fetchProfile·findProfile        → Step 4

  ★ 라우트 표가 통째로 바뀐다 — ƒ(Dynamic) 기호가 사라졌다

    D-4 끝:  ○ /        ƒ /[username]     ○ /explore
    D-5 끝:  ◐ /        ◐ /[username]     ○ /explore

    ○  (Static)             prerendered as static content
    ◐  (Partial Prerender)  prerendered as static HTML with
                            dynamic server-streamed content

8. ⚠️⚠️⚠️ D-4 가 산 404 를 D-5 가 되팔았다
====================================================================

                       D-4 끝          D-5 끝
  /jaehoon 첫 바이트     408ms           5.4ms
  /zzzzz 상태 코드       404             200        ← 되돌아갔다

  /zzzzz 응답 헤더:  HTTP/1.1 200 OK
                     x-nextjs-postponed: 1
                     x-nextjs-stale-time: 300

  본문에는 다 들어 있다:
    "NEXT_HTTP_ERROR_FALLBACK;404" 다이제스트 · noindex
    "없는 주소예요" / "주소를 다시 확인해주세요." / "피드로 돌아가기"

  ★ 화면은 정상이고 상태 코드만 200 이다. 껍데기가 먼저 나가버려
    그 뒤에 상태 코드를 못 바꾼다 — D-4 Step 7 이 발견한 그 법칙이
    이번엔 Cache Components 를 켜는 것만으로 재발했다.

  ★★ 이것이 D-4 Step 7 의 거래를 정확히 뒤집는다.
     D-4: 401ms 를 내고 404 를 샀다.
     D-5: 그 404 를 되팔아 401ms 를 돌려받았다.
     → 껍데기를 넓혀 둘 다 갖는 방법은 다음 회차 소관.

  참고: /zzzzz 첫 방문 stub 4건 — layout 이 notFound() 를 부르는 동안
        page 의 세 요청도 이미 출발해 있다.


9. Step 5 실험 — 예측 가능한 값 / 절대 안 굳는 값
====================================================================

  /explore 는 cacheComponents 를 켜도 아무 에러가 없다 (파일 상수).
  거기에 Math.random() 을 넣으면:

    exit 1
    Error: Route "/explore": Next.js encountered the unstable value
           `Math.random()` while prerendering.
    Ways to fix this:
      - [dynamic] Render at request time by adding a dynamic data access
                  (e.g. `await connection()`) before this call
      - [cache]   Prerender and cache the value with "use cache"
      - [client]  Render the value on the client with "use client"

  ★ Step 2 의 세 갈래([stream]/[cache]/[block]) 와 다른 세 갈래가 나온다.
    Next 는 막을 때마다 그 자리에 맞는 선택지를 준다.

  await connection() + <Suspense> 로 풀면 exit 0 이고
  /explore 가 ○ → ◐ 로 옮겨간다. (실험 후 원복 — 탐색은 굳어도 되는 화면)
