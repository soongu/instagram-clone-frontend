1절. 계획 단계 실행 — proxy 는 정말 404 를 되찾는가 (D-6 이 넘긴 숙제)
════════════════════════════════════════════════════════════════════════
D-6 종료 상태에서 `apps/web-next/proxy.ts` 를 신설:

  export async function proxy(request: NextRequest) {
    const username = request.nextUrl.pathname.slice(1);
    const response = await fetch(`${API_BASE}/users/${encodeURIComponent(username)}`);
    if (response.status === 404) {
      return NextResponse.rewrite(new URL('/_not-found', request.url), { status: 404 });
    }
    return NextResponse.next();
  }
  export const config = { matcher: ['/((?!api|_next|favicon.ico|explore|$).+)'] };

2절. 404 의 가격표 — 5회씩 반복 측정 (같은 기계·같은 빌드·클린 빌드 후)
════════════════════════════════════════════════════════════════════════
                 proxy 없음(baseline)          proxy 있음
  /              200 / 2.1~3.9ms               200 / 2.2~3.9ms
  /explore       200 / 1.9~5.0ms               200 / 1.5~2.5ms
  /jaehoon       200 / 2.0~5.5ms               200 / 404.7~405.7ms
  /zzzzz         200 / 1.6~2.2ms               404 / 403.7~404.7ms

  ★★★ 404 를 되찾는 값 = 프로필 주소 전부의 첫 바이트가 약 2ms → 405ms.
      405ms 의 정체는 api-stub 의 DELAY_MS(400) — proxy 가 "이 사람 있나" 를
      물어보고 답이 와야 첫 바이트가 나간다. 계산이 맞는 통제된 숫자다.
  ★ matcher 가 제외한 / 와 /explore 는 전혀 안 문다 — 무는 범위는 우리가 정한다.

  ⚠️ D-4 는 401ms 를 주고 404 를 샀고, D-5 가 그것을 되팔았고, D-7 이 다시
     405ms 를 주고 되산다. 같은 값을 두 번 지불하는 것이 아니라 지불하는 자리가
     화면 안(D-4) → 화면 밖(D-7) 으로 옮겨간 것이다.

3절. proxy 는 Server Action POST 도 문다 (문서 경고의 실측)
════════════════════════════════════════════════════════════════════════
문서(proxy 「Execution order」):
  "Server Functions are not separate routes in this chain. They are handled as
   POST requests to the route where they are used, so a Proxy matcher that
   excludes a path will also skip Server Function calls on that path."

실측 — api-stub 로그의 `GET /api/users/minji` 증가분:
  POST /minji (Next-Action 헤더 붙여 호출) → +1 건
  GET  /minji                              → +1 건

  ★ 팔로우를 한 번 누를 때마다 proxy 의 존재 확인이 한 번 더 나간다.
    쓰는 요청에는 필요 없는 확인인데 matcher 가 method 를 안 가린다.

5절. revalidateTag 는 "즉시" 가 아니다 — 이 회차 최대 반전
════════════════════════════════════════════════════════════════════════
Route Handler `app/api/revalidate/route.ts` 로 통제 실험 (Next 를 안 거치고
api-stub 을 직접 바꾼 뒤 태그만 버려본다):

  ① 첫 요청            화면 8500 / 원본 8500     (캐시 채움)
  ② api-stub 직접 변경  원본 8501                (Next 는 모른다)
  ③ 다시 화면          화면 8500 / 원본 8501     ← 굳어 있다 (1초 뒤도 8500)
  ④ POST /api/revalidate?tag=profile:minji → {"called":"revalidateTag"}
  ⑤ 바로 다시 화면      화면 8500                ← ★ 아직도 옛 숫자!
  ⑥ 그다음 요청부터      8501 · 8501 · 8501 · 8501 · 8501 · 8501

  ★★★ revalidateTag(tag,'max') 는 stale-while-revalidate 다. 버린 직후
      한 번은 옛것을 더 보여주고 뒤에서 새로 만든다. 문서 그대로:
      "Serves cached data while fetching fresh data in the background"
  ⇒ 자기가 방금 누른 것을 자기가 봐야 하는 자리에서는 이걸 쓰면 안 된다.
    그래서 updateTag 가 따로 있다 (read-your-own-writes).

  ⚠️ 이 차이는 "이름이 다르니 뭔가 다르겠지" 로 넘어가면 안 보인다.
     실제로 한 번 더 요청해봐야만 드러난다.

6절. updateTag 를 Route Handler 에서 부르면 — 에러가 해법을 말한다
════════════════════════════════════════════════════════════════════════
POST /api/revalidate?tag=profile:minji&mode=update  →

  updateTag can only be called from within a Server Action. To invalidate
  cache tags in Route Handlers or other contexts, use revalidateTag instead.
  See more info here: https://nextjs.org/docs/app/api-reference/functions/updateTag

  소스 실측 (next/dist/server/web/spec-extension/revalidate.js):
  · updateTag 는 workStore 가 없거나 `workStore.page.endsWith('/route')` 면 던진다
    (__NEXT_ERROR_CODE E872). 소스에 TODO 주석이 달려 있다 —
    "change this after investigating why phase: 'action' is set for route handlers"
  · revalidateTag 는 2번째 인자가 없으면 console.warn 으로 deprecation 을 찍는다:
    '"revalidateTag" without the second argument is now deprecated, add second
     argument of "max" or use "updateTag".'
    → 2인자가 정본. 1인자 형태는 동작하지만 경고가 뜬다.

7절. Route Handler 는 라우트 표에 다른 기호로 뜬다
════════════════════════════════════════════════════════════════════════
  ┌ ◐ /
  ├ ◐ /_not-found
  ├   /[username]
  │ └ ◐ /[username]
  ├ ƒ /api/revalidate      ← 새로 생긴 줄. 화면(◐)이 아니라 응답(ƒ)
  └ ◐ /explore

  ƒ Proxy (Middleware)

  ★ D-5 에서 ƒ 가 통째로 사라지고 D-6 에서 ○ 마저 사라져 전부 ◐ 였는데,
    D-7 에서 ƒ 가 다른 뜻으로 돌아온다 (그때는 동적 화면, 이번엔 화면이 아닌 것).
