■ 2. Step 1 — 위조한 신원으로 「행동」까지 되나
  위조 접속(me=nobody)으로 /minji 를 열면 팔로우 폼이 통째로 온다:
    $ACTION_REF_2  (값 없음)
    $ACTION_2:0    {"id":"6000c060bee...","bound":"$@1"}
    $ACTION_2:1    ["minji",{"following":null,"message":null}]
    $ACTION_KEY    kd2eec45c3fb1810fecc2c3a2d62171ed
  그 폼을 그대로 POST 하면 액션이 실제로 돈다 →
    [api-stub] POST /api/users/minji/follow      (로그에 찍힘)

  ⚠️ curl 로는 응답 본문을 못 받는다(스트리밍 화면 · 3분 타임아웃).
     D-8 canon 과 동일. 판정은 반드시 부작용(스텁 로그·집계값)으로.
  ⚠️ 처음 POST 는 $ACTION_REF_2 를 빠뜨려(value 속성이 없어 정규식이
     못 잡음) 액션이 안 돌았다. 4개를 다 실어야 한다.

■ 3. api-stub 의 방어선 — 이것은 인증이 아니다

    프로필 주인(게시물 작성자)은 10명이다 —

    안 본다. 실존 계정 이름으로 위조하면 그대로 통과한다.

■ 7. Step 4 척추 — 서명된 쿠키 vs 서명 없는 쿠키
  Set-Cookie: better-auth.session_token=<token>.<서명>;
              Max-Age=604800; Path=/; HttpOnly; SameSite=Lax
    예: RUlYj5NJEYxIWIuEVU3LlI2pV1uzhQvF.bAGOTlwmoKQn1M2T6P3wg0b6IMq89nkx4uJUpm19v9E%3D

  GET /api/auth/get-session 에 쿠키를 실어 보내면
    진짜 (대조군)          → 세션 + 사용자 반환
    쓰레기 값              → null
    토큰 진짜 + 서명만 위조  → null
    서명 진짜 + 토큰만 바꿈  → null

  ⚠️⚠️ 측정 함정 3 (가장 위험했다) — 처음엔 대조군까지 null 이 나와서
     "전부 거절된다" 로 결론 낼 뻔했다. 원인은 curl 이 HttpOnly 쿠키를
     쿠키 항아리에 "#HttpOnly_" 접두사로 저장하는데 grep -v '^#' 로
     걸러버린 것. 대조군이 통과하는지부터 확인해야 나머지가 의미를 갖는다.
     추출은 awk '/better-auth\.session_token/{print $NF}' 로.

■ 14. Step 5 재측정 — 순서가 중요하다
  .env.local 없이:
    next build            → BUILD EXIT 0 · 출력에 Base URL 경고 하나뿐
    프로덕션 GET /         → 200  (모든 화면 정상)
    프로덕션 GET  /api/auth/ok        → 500
    프로덕션 POST sign-in/username    → 500
    서버 로그에만 ⨯ BetterAuthError
  .env.local 을 준 뒤: ok 200 · sign-in 200 · 로그 에러 0

  ⚠️⚠️ 우리가 쓴 .catch(() => undefined) 가 라이브러리의 경고를 삼킨다.
     씨앗 심기의 catch 를 빼고 빌드하면 출력에 BetterAuthError 가 1건 찍힌다.
     catch 를 두면 0건. 어느 쪽이든 BUILD EXIT 는 0.
     → 라이브러리는 알려주려 했고 우리 한 줄이 그것을 삼킨 자리.

  ⚠️ 측정 사고 — 시크릿을 준 뒤에도 500 이 나와서 한참 헤맸다.
     원인은 옛 서버가 3000 을 잡고 있어 새 서버가 EADDRINUSE 로 죽은 것
     (D-3 재현). curl 은 기본 시크릿을 쓰는 옛 서버를 재고 있었다.
     lsof -nP -iTCP:3000 -sTCP:LISTEN -t 로 죽이고 다시 잰다.

  고침: globalThis 에 매단다 —

  ★★ dev 만의 문제가 아니다 — 일부러 되돌려 프로덕션 빌드로 재확인:
